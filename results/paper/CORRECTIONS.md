- 'Snapshots have no replay buffer, target networks or optimizer state, so the critics cannot keep learning' overstates the case. The snapshot keys are as stated (actor, cfg, cost, cost2, lambda, members, step). But the critics could still learn from fresh environment data, which the probe already collects, and the final <stem>.pt files written by train.save_final do hold target networks and optimizer states. Freezing the critics is a design choice, not a necessity.
- The summary says the updates run 'on mean(-Q_bar + lambda Q_c) over those states', which reads as the 5,000 states used for lambda*. The code draws its batches from all 20,000 probe states S, as PROTOCOL.md correctly says.
- The run-cost formula counts one 20-episode evaluation too many per main checkpoint: it uses 2 plus 22, but the true count is 1 plus 22, since R0 is the first of the 22 grid values. The overcount is about 10 minutes and errs on the safe side. Measured here: 8.1-8.6 CPU-h (corrected or as coded), against 9.2 reported, which is consistent given machine load.
- 'I opened no study snapshot, CSV or heldout.json' cannot be proven, but file access times fit it. None of the 45 main checkpoints and none of the S1, S3a or S3b snapshots were accessed today. The same holds for every .json, .csv and heldout.json of the declared runs. Seven S2 snapshots at the 1M trajectory step (seeds 105, 107, 108, 110, 111, 113, 114) were read today at 09:21-09:35. They were read together with undeclared 300k/600k/1.2M snapshots of the same runs, which looks like another analysis rather than the probe's 250k grid. No other analysis script under results/paper or the scratchpad computes action gradients or actor updates.
- Numerical sensitivity of R(lambda), likely the most important point to settle before commit. Each R(lambda) is one deterministic evaluation after K Adam steps. On the M=3 scratch model, changing only the floating-point summation order of the action gradient (heads reading separate (s,a) copies) left actor parameters only ~1e-7 apart after 200 steps, yet 2-episode returns moved by up to 3.5 (R(10): 5.95 vs 2.44). With the probe's summation order, my independent code reproduces every value exactly. The probe is deterministic on this machine, but lambda_half could therefore move under bit-level changes such as another CPU or torch build. This was an untrained model scored on 2 episodes, so it says nothing about the size of the effect in the study. Before commit, consider pre-declaring a DESCRIPTIVE robustness check, e.g. lambda_half under a second batch-sequence seed.
- The overall label folds NOT EVALUABLE into INCONCLUSIVE. Separately, missing declared files do not change the exit status: a fake root in which every co-primary checkpoint was missing printed 'OVERALL ... INCONCLUSIVE' and exited with status 0. All 325 declared files exist today, so this only bites if --root is wrong. Before commit, consider an overall NOT EVALUABLE label and a non-zero exit under --prereg when a declared file is missing.
- The job cache is keyed on the protocol-constants hash and the snapshot SHA, not on probe_sha256. A job written by an earlier probe version with the same constants is reused silently. probe_sha256 is recorded, so this can be audited, but adding it to the cache key is safer.
- No sensitivity to K or step size is pre-declared, as the author acknowledges. The tt sets (S2, S3b) move the actor about 60 times faster than training did. Any such check must be added before commit, or it becomes post hoc.
- Minor labelling: in --stems mode the per-set table says DESCRIPTIVE under an EXPLORATORY header. The --prereg path is consistent: S1 and S2 tables and the overall label are EXPLORATORY; S3a, S3b and the trajectory table are DESCRIPTIVE.
- Figures (scratch plumbing only) are readable. The fixed light background shows the same in dark viewers, the blue/orange/grey palette is colour-blind safe, and axes are labelled with units. Minor points: per-seed lines in probe_trajectory are thin (0.8 pt) at 45% opacity; the 1e-6 floor on training lambda can stretch the log axis over about 6 decades; the 'return-halving point' legend entry appears when no point is plotted; and the S3 panels share an EXPLORATORY figure title, though each panel title says descriptive.
